################################################################################
## Project Description
################################################################################

This is the official website of Google Developer Groups on Campus — Institute
of Business Administration (IBA), Karachi. It promotes the chapter, its events,
speakers, team and story, and lets students join the community.

The site follows the Google Developer Groups (GDG) on Campus visual language:
a playful, outlined, geometric style. Every piece of artwork is built from the
brand's own shape family — pills, circles in a row of three, slanted double
slashes "//", asterisks, globes, people-arches, arrows, braces { }, quote
marks and notched "tab" cards — drawn with a thin near-black outline and filled
with the four Google colours in their halftone and pastel tints.

Compared with the reference chapter site (gdgocdsu.com), this build keeps the
same information architecture (home with embedded sections + separate inner
pages) but is more animated and more colourful: every section has its own
colour theme (Blue / Green / Yellow / Red), floating brand shapes drift and
react to the cursor, marquees never stop, and page-to-page navigation uses
smooth view transitions.

The site is static-first (Astro) with React "islands" only where interaction
is needed (shadcn/ui components, carousels, filters, forms, animation-heavy
pieces). All animation is driven by Motion (motion.dev) plus CSS keyframes for
simple infinite loops. Smooth scrolling comes from Lenis.

Design pillars:
  1. Brand-faithful     — only brand colours, brand fonts, brand shape language.
  2. Vivid but ordered  — big colour fields, but one theme colour per section.
  3. Alive              — floating shapes, marquees, hover reactions, reveals.
  4. Fast and accessible — static HTML first, respects prefers-reduced-motion.

## Colour Palette & Design System
################################################################################

------------------------------------------------------------------------
Design Philosophy
------------------------------------------------------------------------

  Bold outlines, big flat colour fields, friendly rounded forms. Think Google
  I/O stationery: pastel backgrounds, saturated shapes, black line-art.
  Solid colours do the heavy lifting; GRADIENTS are allowed but follow strict
  rules (see "Gradient Rules"). Every section picks ONE theme colour and uses
  that theme's pastel / halftone / core tints. Never mix more than one theme
  in a single section, except in the Google-4-colour accents (logo mark,
  progress dots, confetti, marquee chips).

  VERIFIED AGAINST THE BRAND KIT PDF (all 58 pages read). What the kit's own
  templates (banners, social, announcements, signage, badges, certificates,
  swag) consistently show, and what this site copies:
    1. ONE flat PASTEL field per layout (blue / green / yellow / pink-red).
    2. A WHITE, thin-outlined, rounded "notched" content card sitting on it.
    3. Saturated HALFTONE shapes for the big friendly objects, CORE colour
       for the denser / secondary shapes and name pills, BLACK 02 line-art
       for the globe, people, arrows, asterisk, scallops.
    4. Google Sans Regular headlines with ONE Bold word; Google Sans Mono for
       small "code-style" data.
    5. Every template exists in the SAME FOUR colourways, always in the
       order Blue → Green → Yellow → Pink/Red. The site themes follow suit.
    6. The logo is TINTED to the layout's colourway (not always 4-colour).
  The full pattern inventory is in "Brand Pattern Library" (P1–P13) below.

Gradient Rules (the reference site mixes solid + gradient fills)
------------------------------------------------------------------------

  Gradients are used for atmosphere only, never for text or icon outlines.
  Allowed gradient recipes (all use brand tints):
    G-SUNRISE   linear-gradient(135deg, #FFE7A5 0%, #FFD427 55%, #F9AB00 100%)
    G-SKY       linear-gradient(135deg, #C3ECF6 0%, #57CAFF 60%, #4285F4 100%)
    G-MEADOW    linear-gradient(135deg, #CCF6C5 0%, #5CDB6D 60%, #34A853 100%)
    G-BLOSSOM   linear-gradient(135deg, #F8D8D8 0%, #FF7DAF 60%, #EA4335 100%)
    G-GOOGLE    conic/linear sweep through #4285F4 → #EA4335 → #F9AB00 → #34A853
                (ONLY for thin 4px accent lines and the hero blob glow)
  Where gradients are used:
    - Hero background blob (blurred radial gradient, opacity 0.5)
    - Big hero/CTA shapes (a gradient fill INSIDE a 2px #1E1E1E outline)
    - Text highlight underline on one headline word per page
    - Hover state of primary buttons (solid → gradient shift)
  Where gradients are NEVER used: body copy backgrounds, form fields, footer
  text, the GDG logo, outlines, small icons.
  Keep gradients to ≤ 2 per viewport so the solid flat look still dominates.

Typography (from brand kit)
------------------------------------------------------------------------

  Primary   : "Google Sans"       — weights 400 (Regular) and 700 (Bold)

              Titles/large sentences: mix Bold + Regular IN THE SAME HEADLINE

       — this is the official, licensed route for GDG chapters.
    2. Convert to .woff2 (e.g. using https://cloudconvert.com or `fonttools`)

    4. FALLBACKS (if brand-kit files are unavailable): Google Fonts now offers

         Sans: "Outfit" or "Figtree"  (geometric, similar to Google Sans)
         Mono: "Roboto Mono" or "JetBrains Mono"
       Load via @fontsource (e.g. @fontsource/outfit) — self-hosted, no CDN.

  Font stacks:
      --font-sans : 'Google Sans', 'Figtree', 'Outfit', system-ui, sans-serif
      --font-mono : 'Google Sans Mono', 'Roboto Mono', ui-monospace, monospace

  Scale (use clamp() for fluid headings):
      Hero H1         : clamp(3rem, 9vw, 8rem)   Bold+Regular mix, leading-[0.95]
      Page H1         : clamp(2.5rem, 7vw, 6rem)
      Section H2      : clamp(2rem, 5vw, 3.75rem)
      Card title      : 1.5rem (24px) Bold
      Lead paragraph  : 1.25rem (20px) Regular
      Body            : 1rem (16px) Regular, leading-relaxed
      Mono label      : 0.75–0.875rem, uppercase, tracking-widest
  Text colour is #1E1E1E on pastel/off-white; #F0F0F0 on #1E1E1E.

  KIT TYPE PATTERNS (copy these exactly)
    - STACKED BOLD/REGULAR TITLE: first line(s) Bold, last line(s) Regular,
      same size ("**Brand Messaging**" over "On Campus"). Use for every
      SectionHeading: <h2><b>Meet</b><br/>The Crew</h2>.
    - BOLD WORD INSIDE REGULAR SENTENCE: "Chapter **Title** Goes Here."
      Exactly ONE bold word per headline. Never two.
    - BIG NUMBER + TITLE DIVIDER: a thin-weight number "01." left and a
      Regular 6xl title right (kit section covers). Used for numbered
      sections ("01 / Who We Are") — number in Google Sans Mono on web.
    - LEFT-RAIL LAYOUT: small bold label + 12–14px intro in a narrow left
      column (~22%), wide content on the right (kit Typography pages).
    - THREE-COLUMN TEXT: bold run-in subhead + short paragraph, 3 equal
      columns (kit Brand Messaging page) → used in About pillars and Our

    - TINY BREADCRUMB HEADER: 11–12px line across the top of a page
      ("Google Developer Groups On Campus   ·   Events   ·   Upcoming") —

    - Mono is for: dates, times, role tags, speaker/talent names on promo
      pills, stats captions, section numbers. Never for paragraphs.
    - Paragraph rule from the kit: "For paragraphs with smaller type point,
      use the Regular variable." Bold is for titles and emphasis only.

Shape & Line Language
------------------------------------------------------------------------

  - Outline weights (scaled from the kit): 1.5px on notch cards, photo
    frames and line-art icons; 2px on filled shapes and pills; 3px only on
    hero-scale shapes (> 240px). Stroke colour always #1E1E1E. Use
    vector-effect: non-scaling-stroke so weights stay constant when SVGs
    are resized.
  - Radius scale (shadcn --radius overridden to 1.5rem):
        pill        : rounded-full (buttons, chips, tags, inputs)
        card        : rounded-3xl (24px)
        notch card  : special "tab" shape (see below)
        image       : rounded-2xl; featured images use the notched crop
  - NOTCHED CARD ("tab card") — the signature brand container: a rounded
    rectangle with one rounded cut-out in a top corner, creating a "tab" that
    carries a label (e.g. "Event", "Upcoming", "Agenda"). Build as an SVG
    clip-path/mask component <NotchCard notch="top-left|top-right|bottom-right">
    with the 1.5px outline following the notch path. White fill by default.
    FULL GEOMETRY of the two notch types is in Pattern Library P2.
  - Row of three circles (people / signal motif), double slash "//", 8-point
    asterisk, globe (3 lines + ellipse), three arched "people" shoulders,
    long arrow with curved head, braces { } and quote marks are the standard
    decorative vocabulary. All are in src/components/shapes/.
  - Hard offset shadow for lifted cards on hover: 4px 4px 0 #1E1E1E (no blur).
    Soft blurred shadows are NOT used.

## Brand Pattern Library (read directly from the GDG on Campus brand-kit PDF)
################################################################################

  Everything below is what the kit's 40+ templates actually do. Build these
  as reusable components first (Order of Work step 4) and every page then
  becomes assembly.

------------------------------------------------------------------------
P1. Shape vocabulary (name → look → where the kit uses it → component)
------------------------------------------------------------------------

  SLASHES "//"        Two slanted parallelograms. Filled (halftone) or
                      outline-only (#1E1E1E). Cover, banners, signage,
                      certificates. → <Slashes variant="filled|outline">
  TRIPLE CIRCLE       Three equal circles in a row, halftone fill + 1.5px
                      outline. The kit's most common "people/community"
                      signal. → <TripleCircle layout="row|stack">
  MERGED CIRCLES      Three overlapping circles fused into one outlined
                      "caterpillar" blob (cover, rectangle sticker,
                      meterboard). Variant: vertical outline-only stack
                      (venue template). → <TripleCircle merged>
  PEOPLE ARCHES       Row of 3–4 open arches (shoulders) under the circles.
                      Line-art only. → <People count={3|4}>
  SCALLOPS            Row of arches "︵︵︵" or inverted "︶︶︶". Used as
                      section divider, lanyard filler, banner decoration.
                      → <Scallop dir="up|down" count>
  GLOBE               Circle + vertical ellipse + 2 horizontal lines, thin
                      line-art. Appears on ~80% of templates. → <Globe>
  ASTERISK            8-point asterisk, line-art. → <Asterisk>
  ARROWS              (a) long thin line arrow with curved open head,
                      pointing left or right (outline); (b) BLOCK ARROW:
                      chunky filled arrow (core/halftone + outline),

                      dir>
  BRACES              (a) thin "{ }" curly braces framing "On Campus";
                      (b) chunky FILLED bracket "]" with a stepped inner

  HASH "#"            Chunky rounded hash, filled core + outline (agenda,

  QUOTES              Open ‘‘ and close ’’ marks, outline or filled core

  COMMA / SEMICOLON   Filled comma under a dot (avatar template, activity
                      V2). → <Comma>
  PIN                 Location pin, halftone fill, circle hole (venue). →
                      <Pin>

  LINES "="           Two or three short parallel strokes. → <Lines>

                      <Bars>
  CODE HEART "<3"     Chevron + 3 glyph (blog, photo frames). → <CodeHeart>

                      sticker) → use for the dark/light or "Join" toggle
                      micro-interaction.
  THE MARK            Two chevrons "< >" made of 4 capsules (red top-left,

  Rules: never stretch shapes non-uniformly, never rotate the globe,
  never put two block shapes of the same colour touching, and keep ONE
  hero-scale shape per viewport (the rest are small accents).

------------------------------------------------------------------------
P2. Notch card geometry (the brand's signature container)
------------------------------------------------------------------------

  Two types. Both: white fill, 1.5px #1E1E1E outline, outer radius ≈ 28px
  (≈ 2.8% of the card's short side, clamp 20–32px), INNER (concave) joins
  rounded with the same radius so the outline is one continuous path.

  TYPE A — LABEL TAB (event / upcoming / venue / agenda / badge role)
    A small rounded rectangle "tab" rises from the TOP-LEFT of the main
    card and shares its outline. Tab holds a short label in Google Sans
    Regular ("Event", "Upcoming", "Venue", "Agenda"). The empty space to
    the right of the tab is filled with a long line-arrow (←) or logo.
    Role pills (Attendee / Staff / Speaker / All Access) are the mirrored
    case: a coloured pill tab at the BOTTOM-LEFT of the card.
    → <NotchCard type="tab" tabPosition="top-left|bottom-left"
       label="Event" />

  TYPE B — STEP CUT-OUT (social, signage, one-sheet, 16:9, photo frames)
    One or two rectangular STEPS are cut from corners, leaving an L-shaped
    card:
      • top-right step  → holds the asterisk box / globe / arrow
      • bottom-right step → holds the logo lockup (very common)
      • top-left step   → holds the row of three circles (1:1 and 4:5)
    The step size is about 28–35% of card width × 12–18% of height.
    → <NotchCard type="step" notches={["top-right","bottom-right"]} />

  Implementation: generate the path in JS from (w, h, r, notches) and render
  as an SVG <path> with fill white + stroke; place content with CSS grid
  areas and clip with the same path (clipPath: url(#id)). Use
  ResizeObserver so the path redraws responsively. Keep the content
  padding at 8–10% of width.

  Layout recipe ("the template"): pastel background → NotchCard filling
  ~75% → decorative shapes in the free notch spaces → logo bottom-right.
  Used for: Hero feature card, EventCard, SpeakerCard, About card,
  Story milestone, CTA band, Contact panel.

P3. Photo frames & avatars
------------------------------------------------------------------------

  PHOTO FRAME (kit "Photo Frames", landing/Twitter/LinkedIn banners):
    Photo cropped inside a rounded rectangle (radius ≈ 24px) with ONE or two
    stepped corners, 1.5px #1E1E1E outline. The stepped corner holds the
    chevron mark (top-left) or a line icon (asterisk / <3 / ← / globe,
    bottom-right). The frame colour is the theme pastel; a 12–16px pastel
    border surrounds the photo. Each team/speaker/gallery image uses a
    DIFFERENT icon in the corner and rotates through the 4 themes.
    → <PhotoFrame theme icon="asterisk|code-heart|arrow|globe"
       logoCorner="top-left" />
    The gallery hover (G4) reveals the same frame.

  AVATAR (kit "Avatar Template"): circular photo, 1px outline, with three
    coloured corner overlays on the circle edge:
      – top-left: theme-halftone tab holding a tiny globe + a pastel comma
      – right-middle: two stacked core-colour dots
      – bottom: white pill holding the chevron mark, bottom-right tab in pastel
    → <AvatarFrame theme src />  Use for Team cards and the hero's "Join
    N+ members" avatar stack.

  PHOTOGRAPHY STYLE (from the kit's samples): real, candid, natural-colour
  photos — crowds at talks, people at laptops, portraits against softly
  blurred backgrounds. No heavy filters, no duotone, no stock-looking
  handshakes. Keep faces centred; crop to the frame's notch.

P11. Accessibility adaptations (kit look vs. WCAG on the web)
------------------------------------------------------------------------

  - The kit sets the chapter name in the core colour on pastel (e.g. #34A853
    on #CCF6C5 ≈ 2.4:1). Keep that ONLY inside the logo SVG (it has an
    accessible name). For readable text always use #1E1E1E.
  - Halftone fills behind text must be paired with #1E1E1E text only.
  - Core fills (#4285F4, #34A853, #F9AB00, #EA4335) carry #1E1E1E text
    (≥ 3.9:1; fine for the large sizes used).
  - Every decorative shape: aria-hidden="true", focusable="false".
  - Focus ring #4285F4 3px + 2px offset on pastel; on blue fills use #1E1E1E.

------------------------------------------------------------------------
P12. Naming & copy rules from the kit (page 3)
------------------------------------------------------------------------

  - Group: "Google Developer Group on Campus Institute of Business
    Administration" or "GDG on Campus IBA". Avoid the bare umbrella term
    "GDG".
  - Organizer title: "Google Developer Groups on Campus Organizer" /
    "GDG on Campus Organizer" (Team page lead role, LinkedIn-style bios).
  - Social hashtag: #GDGOnCampus on every share, footer and OG text.

------------------------------------------------------------------------
P13. Don'ts (from the kit's own restraint)
------------------------------------------------------------------------

  - No drop shadows / glows on shapes (hard 4px offset only on hover).
  - No gradients on shapes inside templates — the kit is flat colour. (The
    site's gradients stay in the atmosphere layer only; see Gradient Rules.)
  - No more than one colourway per layout, no rainbow backgrounds.
  - No bold paragraphs, no all-caps headlines (all-caps is for Mono labels).
  - No third-party or competing logos near the lockup without clear space;
    partner logos sit in white circles (kit sponsor template).

## Global Animation Patterns
################################################################################

  Scroll reveal (default)  : y:40 → 0, opacity 0 → 1, 0.6s, ease [0.22,1,0.36,1],
                             viewport once, amount 0.2
  Stagger                  : 0.06–0.1s between siblings
  Hover (cards)            : translate(-4px,-4px) + hard shadow 4px 4px 0 #1E1E1E,
                             0.2s ease-out
  Hover (pills/chips)      : scale 1.06, rotate ±2–3°, spring (stiffness 400,
                             damping 18)
  Tap                      : scale 0.97
  Floating shapes          : translateY ±14px, rotate ±4°, 6–10s ease-in-out
                             infinite alternate, random delays
  Cursor parallax          : useSpring(stiffness 120, damping 20), depth 6–24px
  Marquees                 : linear infinite, 30–50s, pause on hover
  Page transitions         : Astro ClientRouter; old page fades/slides up 0.25s,
